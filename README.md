# StayMate-AI26 — Sunny Stay 晴旅小屋 (V2.2)

本機課程示範：**LLM + Agent (Tool Calling) + RAG (TF-IDF)**，加上會員登入、查房、SQLite 訂房、會員個人訂單與全站浮動 AI 客服。

## 本機執行

1. 使用 Python 3.10+，在虛擬環境中執行 `pip install -r requirements.txt`。
2. 複製 `.env.example` 為 `.env`，只在自己的電腦填入學校提供的 `MODEL_NAME`、`API_KEY`、`LLM_API_URL`。**不要將 `.env` 上傳 GitHub。**
3. 執行 `python app.py`，瀏覽 `http://127.0.0.1:7860`。
4. 免登入可使用「AI 客服」及右下角浮動 AI。註冊會員後可查房並建立模擬訂單，再問 AI「我的訂單有哪些？」。

## AI 三大技術

- **LLM**：透過學校 OpenAI-compatible API 呼叫 `MODEL_NAME`。
- **Agent**：`run_agent` 根據需求呼叫 `list_rooms`、`check_room_availability`、`get_my_bookings` 等工具，並顯示 Tool Trace。
- **RAG**：`rag_tfidf.py` 以 TF-IDF 從 `hotel_rules.txt` 搜尋相關政策，再提供給 LLM。

## 訂房與安全

- 訪客可查詢房型與模擬庫存，但只有已登入會員能建立、查詢或取消自己的訂單。
- `prepare_booking` 只建立建議草稿；正式訂單由顧客在訂房頁按下確認後才寫入 SQLite。
- 會員查詢工具從伺服器驗證的 session 取得身分，AI 不可指定 user_id。
- 訂房以 SQLite `BEGIN IMMEDIATE` 交易重新檢查每晚庫存，避免超額訂房。
- `hotel_app.db` 與 `bookings.db` 均為本機產生，不上傳 GitHub。
- 這是虛構飯店與模擬訂單，不含真實付款、真實房間庫存或商用登入安全保證。登入工作階段保存在本機記憶體，重新啟動後須重新登入。
# Sunny Stay 晴旅小屋｜AI 智慧飯店客服與訂房系統

## 一、專案介紹

Sunny Stay 晴旅小屋是一套使用 Python 與 Gradio 開發的 AI 智慧飯店客服與訂房系統。

本專案整合大型語言模型（LLM）、Agent 工具呼叫（Tool Calling）、檢索增強生成（RAG）及 SQLite 資料庫，提供房型查詢、價格比較、會員管理、線上訂房、訂單查詢與 AI 客服等功能。

系統的主要目標是讓旅客能夠快速取得正確的飯店資訊，減少人工客服的負擔，並透過資料庫查詢與文件檢索，降低 AI 產生錯誤資訊的可能性。

## 二、網站頁面與功能介紹

### 1. 首頁（Home）

首頁是晴旅小屋網站的主要入口，提供飯店的基本介紹與服務資訊。

主要功能：
- 展示晴旅小屋的品牌形象與飯店介紹。
- 提供網站各功能頁面的導覽入口。
- 協助旅客快速了解飯店提供的服務。

### 2. 房型介紹（Rooms）

房型介紹頁面展示晴旅小屋提供的各種房型，方便旅客在訂房前比較不同選擇。

主要功能：
- 顯示房型名稱、房間介紹及每晚價格。
- 提供不同房型的資訊供旅客比較。
- 房型資料由 SQLite 資料庫提供，避免價格資訊不一致。

### 3. 會員註冊與登入（Member）

會員頁面提供旅客建立帳號及登入系統的功能。

主要功能：
- 註冊會員帳號。
- 登入及登出會員。
- 透過登入狀態識別會員身分。
- 讓會員使用個人訂房紀錄查詢等功能。

### 4. 空房查詢與線上訂房（Booking）

此頁面提供旅客查詢房間空房情況及建立訂房紀錄的功能。

主要功能：
- 選擇入住日期與退房日期。
- 選擇想預訂的房型。
- 輸入入住人數。
- 查詢房間是否可以預訂。
- 計算住宿總金額。
- 確認訂房後，將訂單資料寫入 SQLite 資料庫。

此功能展示了系統的資料庫寫入能力，訂房資料不只是顯示在畫面上，而是可以保存並供後續查詢。

### 5. 我的訂單與取消訂房（My Bookings）

此頁面讓已登入的會員查看及管理自己的訂房紀錄。

主要功能：
- 查詢會員目前的訂房紀錄。
- 顯示訂單編號、房型、入住日期、退房日期、住宿金額及訂單狀態。
- 提供取消訂房功能。
- 將訂單狀態變更保存至 SQLite 資料庫。

會員可以在日後重新登入網站，查詢已建立的訂房紀錄。

### 6. AI 智慧客服（AI Chat）

AI 智慧客服是本專案的核心功能，使用 Furen-large 語言模型理解旅客提出的自然語言問題。

主要功能：
- 查詢飯店基本資訊。
- 查詢與比較不同房型。
- 計算指定入住天數的住宿費用。
- 協助查詢空房與訂房相關資訊。
- 回答入住、退房、寵物及取消訂房等飯店規定。
- 在無法確認資訊時，說明限制或建議聯絡人工客服。

**Agent 工具呼叫（Tool Calling）**

AI 可以根據旅客的問題，自動選擇適合的 Python 工具，例如：

| 工具名稱 | 功能 |
|---|---|
| `get_hotel_info` | 查詢飯店基本資訊 |
| `get_room_info` | 查詢指定房型資料 |
| `list_rooms` | 列出所有房型及價格 |
| `compare_rooms` | 比較不同房型 |
| `calculate_stay_total` | 計算住宿總費用 |
| `check_room_availability` | 查詢房間可預訂情況 |
| `prepare_booking` | 協助準備訂房資訊 |
| `get_my_bookings` | 查詢已登入會員的訂房紀錄 |
| `search_hotel_rules` | 搜尋飯店規定 |
| `transfer_to_human` | 建議轉由人工客服協助 |

**RAG 檢索增強生成**

系統使用 TF-IDF 技術搜尋飯店規定文件 `hotel_rules.txt`，找出與旅客問題最相關的內容，再提供給語言模型產生回答。

例如旅客詢問「可以攜帶寵物入住嗎？」時，系統會搜尋飯店的寵物政策，而不是讓 AI 自行猜測規定。

### 7. 系統測試（Testing）

本專案包含測試程式，用來檢查 AI 工具呼叫及資料檢索功能。

主要測試項目：
- 基本功能及 API 測試。
- AI 工具選擇是否正確。
- RAG 是否能找到相關飯店規定。
- AI 是否能依照問題選擇適當的工具。

測試功能有助於開發者在修改程式後，檢查系統是否仍能正常運作。

### 8. 浮動式 AI 客服視窗

除了獨立的 AI 客服頁面，網站也提供浮動式 AI 客服入口。

旅客在瀏覽飯店資訊時，可以透過浮動客服視窗詢問問題，不需要特別切換到 AI 客服頁面。

## 三、使用技術

| 技術 | 用途 |
|---|---|
| Python | 主要程式開發語言 |
| Gradio | 建立網站及互動介面 |
| Furen-large | AI 語言理解與回答 |
| Agent / Tool Calling | 讓 AI 呼叫 Python 工具 |
| SQLite | 儲存飯店、會員及訂房資料 |
| TF-IDF | 檢索飯店規定文件 |
| RAG | 提供與問題相關的文件內容 |
| python-dotenv | 讀取環境變數與 API 設定 |

## 四、系統運作流程

1. 旅客進入晴旅小屋網站。
2. 旅客可以瀏覽房型、查詢空房或詢問 AI 客服。
3. AI Agent 根據問題選擇合適的工具。
4. 房型、價格及訂單資訊透過工具從資料庫取得。
5. 飯店規

## 模組化目錄說明

- `services/booking_service.py` 是實際使用的會員、庫存及訂房邏輯；`booking_backend.py` 是舊版匯入相容層。
- `services/auth_service.py`、`services/room_service.py`、`database/connection.py` 提供可重用介面。
- `tools/booking_tools.py` 提供獨立查房與個人訂單查詢介面。
- `pages/*.py` 目前是頁面元件的起點；**完整的 Gradio 頁面與 AI Agent 事件綁定仍在 `app.py`**，尚未完成全部 UI 拆分。
- `rag_tfidf.py` 是 RAG 實作；`app.py` 保留 LLM Agent Tool Calling。

此版本重點是保持原有可執行的展示程式，同時建立後續拆分目錄；不要把目錄存在誤認為所有程式已完成分層。
